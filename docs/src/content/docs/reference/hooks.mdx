# Hooks

mage has no background daemon and no watcher process. It
rides the events your coding host already fires. When you run
[`mage connect`](../reference/commands.mdx), mage writes a small set of `mage:*`
hook groups into your host's settings (for Claude Code, `.claude/settings.local.json`),
each tagged with a stable `id` so mage can update or remove exactly its own groups
and never touch yours. The host calls these commands at the right
moment — when nothing happens in the host, nothing runs.

The table below is generated from the `MAGE_HOOKS` list in the code (via
`pnpm docs:gen`) and guarded by a drift test, so it always matches what
`mage connect` actually installs.

## How to read the table

Each row is one hook group mage owns:

- **Event** — the host lifecycle moment that fires the command (for example
  `SessionStart`, `PostToolUse`, `Stop`).
- **Hook id** — the stable `mage:<role>:<event>` tag. mage upserts and removes
  groups by this id, so re-running `mage connect` is idempotent and self-healing
  (a drifted command is replaced in place). `mage doctor` compares the installed
  ids against this list to detect drift. Groups written by a pre-id mage carry no
  tag; see [Who owns a hook group](#who-owns-a-hook-group--write-repair-detect).
- **Command** — the mage CLI invocation the host runs. They are
  hidden plumbing you never type by hand; see the [Commands reference](../reference/commands.mdx).
- **Purpose** — what that hook does.

## Who owns a hook group — write, repair, detect

Three commands touch the same hook block, and they must agree on one question:
*which groups are mage's?*

- **write** — `mage connect` upserts one group per row in the table above.
- **repair** — `mage doctor --fix` strips mage's groups and re-adds them, healing a
  block that drifted across a version bump.
- **detect** — `mage doctor` (no `--fix`) compares what is installed against the
  table and reports missing, stale, or duplicated registrations.

Ownership is decided two ways, in order. A group whose `id` starts with `mage:` is
mage's. A group with **no** `id` is mage's only if **every** command inside it is one
mage itself writes — matched exactly against a closed list (the commands in the table,
plus the ones older mage versions wrote). An exact list, not a `mage ` prefix: your own
`mage learn` hook, or a group where you added a second command of your own, stays
yours and is never rewritten or removed.

### Legacy id-less groups

mage versions before hook ids wrote groups with no `id`, and nothing ever reaped them.
Upgrading added a correctly tagged group *beside* each orphan instead of replacing it,
so the same command could fire several times per event while `doctor` still called the
block healthy. `connect` now reaps them, and `doctor` counts them.

### Worked example

A settings file carrying the full legacy shape: 33 id-less orphans, the 11 correctly
tagged groups, and one `mage learn` hook of the user's own:

```text
$ jq '[.hooks[][]] | length' .claude/settings.local.json
45    # 33 id-less orphans + 11 tagged mage:* + 1 of mine

$ mage doctor
✗ connection          : local: hook block out of date (mage:* drift: missing=[none] stale=[none] duplicate-registrations=33); re-run `mage connect`

$ mage connect --yes
✓ Wired 11 events into /home/you/project/.claude/settings.local.json (personal settings file).
  Reaped 33 legacy/duplicate mage hook registration(s).
  Run `mage disconnect` to remove.

$ mage doctor
✓ connection          : local: mage hooks current

$ jq '[.hooks[][]] | length' .claude/settings.local.json
12    # 11 tagged mage:*, plus the `mage learn` hook: untouched
```

Four registrations per event collapse to one; the user's own hook survives every step.
`mage doctor --fix` reaches the same end state without a `connect`.

## The hooks that matter in 0.0.18

- **`mage memory-hook`** (PreToolUse, Write and Edit) denies the first rung-less memory write of a session and agent once, after keeping a copy in `notes/.held/`. `ladder.gate: "deny-once"` is the default; `"ask"` is opt-in. See [Capture](../loop/capture.md).
- **`mage recall-hook`** (PreToolUse, Bash, Write, Edit, MultiEdit and NotebookEdit) injects an admitted note whose `trigger.match` hits the call, once per session. It adds context and never blocks. See [Recall at the action](../model/recall.md).
- **`mage index --hook`** (Stop) re-indexes only when a note changed, quietly and without blocking.
- **`mage skills --metrics --quiet`** (Stop) keeps the context-match rollup current for [Optimize](../loop/optimize.md).

The `mage observe` and `mage nudge` rows still appear in the table. They belong to the cut loop (ADR-0060): the code stays until #223 removes it.

Every hook is fail-open: a hook that errors stays out of your way and the host keeps going. mage is memory, not a gate; the one exception is a write the secret scan could not check, which the memory hook denies.
