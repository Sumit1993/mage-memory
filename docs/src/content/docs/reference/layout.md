A mage knowledge base is just files in a directory. There is no database and no hidden store: everything mage knows lives in plain markdown and JSON you can open, diff, and own in git. This page is the map of that directory — what each part holds, and the single most important distinction: **what gets committed versus what stays gitignored.**

## The docs root

Everything below lives under one directory called the **docs root**. Where that is depends on how you set mage up:

- **In-repo** (the common case): the docs root is `mage/` inside your code repository. mage writes only under `mage/`; your application source is never touched.
- **Hub**: a standalone knowledge base repository. There the docs root *is* the repository root.

In the examples below, paths are shown for the in-repo case (the `mage/` prefix); in a hub, drop the `mage/` and read the same names at the repository root.

## The committed surface — what you own

These are the files mage intends you to keep in git. They are the knowledge base: human-readable, Obsidian-navigable, and reviewable in a pull request.

```
mage/
  metadata.json        KB identity, mode, hub links, and the grooming dial (committed config)
  INDEX.md             the full index — one line per memory-genre note (generated, committed)
  MEMORY.md            the pushed roster your host auto-loads (generated, committed)
  notes/               your notes — one markdown file per thing you learned
  decisions/           ADRs: a choice, its reasoning, and what it rules out
```

Plus a few other generated, committed markdown files at the root depending on your setup — for example `Dashboard.md` and a per-wing `_index.<wing>.md`. The rule of thumb: **markdown files and the content directories are the knowledge base, and they belong in git.**

- `notes/` and `decisions/` are content directories — the things you author (with mage's help) and review. An older knowledge base may also hold `work/`: it is retired (ADR-0050), plans and task lists live in the issue tracker, and `mage init` no longer creates it. `mage migrate` counts what is left there and leaves it in place.
- `INDEX.md` and `MEMORY.md` are both regenerated by `mage index` and both committed — they are the two recall surfaces. `INDEX.md` is the full index a reader *pulls* to see what is known without loading every note; `MEMORY.md` is the ranked, budget-bounded roster the host *pushes* at session launch, ending in an overflow line back to `INDEX.md`. `INDEX.md` is byte-deterministic from the notes; `MEMORY.md`'s ordering also consults local usage metrics, so its order can differ between machines. See [The graph](../model/graph.md#the-two-recall-surfaces) and [Notes](../model/notes.md).
- `metadata.json` is the KB's config: its identity, its mode (in-repo / hybrid / external), any hub links, the optional `redact` allowlist for the redaction gate, and the optional `genres` map for custom note-type to genre overrides. See [Redaction (two gates)](./redaction.md).

## The gitignored machine state

mage also writes transient, machine-owned working state. This is **never meant to be committed** — it is rollups and per-session state that mage regenerates or rebuilds as it runs. It all lives under a single gitignored `.mage/` directory at the docs root (ADR-0025), with one leaf per kind of state:

```
mage/
  .mage/               all machine-owned working state — gitignored (ADR-0025)
    metrics/           context-match rollups
    recall/            per-session recall de-dup state
```

Each leaf holds a different kind of working state:

- **`.mage/metrics/`** — generated rollups (read-only for you, written by mage as it runs): the context-match results, i.e. did the skills that auto-loaded actually match the work? Files an older version wrote here lost their writers in #208 and #210; `mage migrate` removes them.
- **`.mage/recall/`** — one small state file per session that remembers which notes [recall at the action](../model/recall.md) already injected, so a note is injected once. A compaction clears it.
- Older versions also wrote `.mage/learnings/` (a capture trail) and `.mage/staging/` (lesson drafts). Nothing in 0.0.18 reads them; delete them when you like.

### Hub clones live at a machine level, not under the docs root

External and hybrid mode ([Set up a hub and external mode](../guides/hub-and-external-mode.md)) reach into a *second* gitignored location that isn't under `mage/.mage/` at all: `~/.mage/hubs/<host>/<owner>/<repo>` (`$MAGE_HOME/hubs` when set). This is where a hub's own clone is derived and lands — one conventional home per remote, shared across every repo and worktree that links to it. Unlike the rest of this page, it is **not** disposable scratch: it is an ordinary git clone with its own history, and it may hold committed notes, unpushed commits, or uncommitted edits. It is regenerable only in the sense that a remote clone always is — push or otherwise back up anything not yet on the remote before deleting it.

### Why these stay out of git

The split is by lifecycle, not by feature: `notes/` is durable, reviewed knowledge you own; everything under `.mage/` is regenerable working state that would only add churn and noise to your history. Keeping it gitignored also means raw captured signal never lands in a shared commit by accident.

mage keeps this ignored for you. When you run `mage connect` (or `mage init`), it self-heals your `.gitignore`, adding the `.mage/` pattern at the right root:

- in-repo, at the code-repo root: `mage/.mage/`
- in a hub, at the hub root: `.mage/` plus its `**/.mage/` recursive form (so each project's state is covered).

If you ever suspect this is not ignored, `mage doctor --fix` re-adds the missing `.mage/` rule.

## Quick reference

| Path (in-repo) | Kind | In git? |
| --- | --- | --- |
| `mage/metadata.json` | config | committed |
| `mage/INDEX.md` | generated index | committed |
| `mage/MEMORY.md` | generated roster (pushed at session launch; order consults local metrics, so it varies by machine) | committed |
| `mage/notes/`, `mage/decisions/` | content | committed |
| `mage/.mage/recall/` | recall de-dup state | gitignored |
| `mage/.mage/metrics/` | rollups | gitignored |
