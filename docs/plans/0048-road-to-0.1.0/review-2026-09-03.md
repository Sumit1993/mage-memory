## A. Contradictions with an ADR the plan marks keep or unchanged

- **blocks merge. ADR-0033 and ADR-0006 versus ADR-0048 decision 7.** Decision 7 is "Native
  auto-memory is off. Capture reaches the store only through mage's own hooks." ADR-0033's whole
  decision is "with `autoMemoryDirectory` = docs root, CC auto-loads MEMORY.md at session launch."
  `MEMORY.md` has exactly one loader: the commandeer tier. `src/agents-md.ts` writes an AGENTS.md
  block that points at `INDEX.md`, never at `MEMORY.md`, in all three modes (`mageBlock`,
  `externalBlock`). So turning auto-memory off deletes the roster's only delivery path. Yet
  ADR-0048 amends 0006 and 0033 to "roster bounded to admitted notes" and the plan's section 6
  (HTML:277) says "Roster stays, bounded to admitted notes". A bounded roster nothing loads is not
  a roster. Fix: **change the plan**. Either name the replacement carrier (an `@import` in the
  AGENTS.md block is the obvious one, and it is not in any work package) or state that MEMORY.md
  is retired and amend 0006, 0033 and 0039 accordingly.
- **blocks merge. ADR-0046 section 5 versus ADR-0048 decision 5.** ADR-0046 section 5:
  "That committed field is the switch's **only** carrier. No environment variable and no flag may
  enable it." ADR-0048 decision 5: "`connect` records which of them accept a pull request on this
  machine." `connect` writes `.claude/settings.local.json` (`src/commands/connect.ts:86`,
  `resolveSettingsTarget`), which is a gitignored machine-local carrier. The amendment banner
  already committed at `mage/decisions/0046-...md:33` asserts "consent was recorded at connect"
  while section 5's body, three screens below, still says the committed field is the only carrier.
  The tree now contradicts itself inside one file. Fix: **amend the ADR** (edit 0046 section 5
  itself, not only its banner) or **change the plan** to put consent in the KB's committed
  `grooming` block.
- **blocks merge. ADR-0045 section 10 and ADR-0047 section 1 versus ADR-0048 decision 5.**

  key path to variable name auto-mints a carrier for every field anyone ever adds, **including

  section 2 rules that policy is read from the knowledge base and never from the code repo. A
  connect-recorded, machine-local landing-consent is a write-enable in a carrier no ADR grants it.
  Both ADRs are marked keep and unchanged (HTML:290; ADR-0048:97). Fix: **amend 0047** with a new
  carrier row, or **change the plan** to a committed policy field.
- **blocks merge. ADR-0016's hard ceilings versus proposal type `delete`.** ADR-0016 section 3:
  "Hard ceilings, never loosen at any rung: never auto-commit, never touch a bespoke hand-authored

## C. Mechanisms the plan relies on that do not exist and are not in the New issues table

- **blocks merge. There is no way to match a `tool_attempt` to its `PostToolUse`.** Section 2
  (HTML:169) defines `prevented` as "PreToolUse attempt event without a matching PostToolUse
  (deny)". ADR-0015 decision 1 explicitly refuses a sequence number: "**No `seq`** ... a monotonic
  counter would force a read-before-append", and the `tool_use` payload (inventory section 6, and
  ADR-0015 section 4) carries `tool`, `paths`, `detail`, `ok`, `error_summary` and nothing that
  identifies one invocation. Two Read calls on the same path in one turn are indistinguishable.
  Adding a correlation id is permitted (additive) but is in no issue: not N3, not L4. **Blocks P2**
  and blocks the 0.1.0 gate, since `prevented` is one of the two gate numbers.
- **fix before P1. Nothing installs the new PreToolUse observe arm on an existing KB.**
  `MAGE_HOOKS` (`src/adapters/claude-code/settings.ts:80-131`) is written by `connect`. N3 adds an
  arm; section 6 (HTML:280) makes `connect` install it. But every already-connected unit gets its
  hooks only from a re-run of `connect`, and migrate as specced (N1) only *removes* groups. So the
  units that P0 measures will emit no `tool_attempt` until someone re-runs `connect` in each one.
  No issue says so. **Blocks P0's counts.**
- **fix before P2. Nothing fires the review-findings puller.** end-to-end.md:49 "The review puller
  is a script, not a verb". ADR-0009 permits no daemon and `MAGE_HOOKS` can only wire `mage <verb>`
  commands. A script with no verb and no hook event is invoked by nobody. Name the trigger
  (SessionStart? a kit hook? the operator?) in L1.
- **fix before P2. The ledger has no defined file, path, schema or writer.** L4 is "fire ledger /
  Definition in section 2. Committed in the KB." Section 2 defines three counting *sources*, not a
  format. Nothing says who appends a row, which is the whole difficulty for a CI-status fire.
- **fix before P2. There is no landing zone for a git hook.** Section 4 names three zones: project
  (`.claude/settings.json`, CI, lint, pre-commit), user (the kit), local
  (`settings.local.json`). The routing table routes `agy-commit-message-compliance-is-unreliable`
  to "mage-memory `.git/hooks/commit-msg` (harness settings)", WP-8 lands a "commit-trailer hook
  (repo)", and the open ruling at HTML:479 hedges "(case 3, if it lands user-scope)". `.git/hooks/`
  is per-clone, uncommittable and in none of the three zones, though mage already installs the
  redaction pre-commit hook there. Either add the zone or say every rung-3 hook is a harness hook.
- **fix before P2. `mage init` still scaffolds `work/`.** `src/commands/init.ts:166` creates
  `[NOTES_DIR, WORK_DIR, DECISIONS_DIR, ARCHIVE_DIR]`. Decision 9 retires `work/`. No issue touches
  `init`. Every KB created after 0.0.19 will be born with a retired directory.
- note. The `dead` surface uses a 90-day window (HTML:171) while `dream --stale-days` defaults to
  180 (inventory section 1). L5 does not say whether it reuses the dial or introduces a second one.

## Verdict

**Merge PR #206** as a proposed ADR plus its plan folder, but fix four things in the ADR file in
this PR first: the routing counts that sum to 34 instead of 39, the effect list that omits five of
the twelve ADRs the plan amends, the roster-versus-auto-memory contradiction in decision 7, and the
carrier conflict in decision 5. Those are edits to one file. Merging a proposed ADR that names its
own errors is cheaper than holding a branch that fourteen documents already cite; merging section 6
of the HTML as an authoritative ADR map is not, because it is already stale against its own branch.

Counts, 54 findings: 8 blocks merge, 2 fix before P0, 17 fix before P1, 16 fix before P2, 11 note.
Two of the P0 and two of the P2 findings are carried in section F's table rather than as bullets.

The three that matter most:

1. **Decision 7 turns off the only loader `MEMORY.md` has, while decisions 6 and the plan keep the
   roster.** `autoMemoryDirectory` is the sole mechanism; `src/agents-md.ts` points at `INDEX.md`
   and never at `MEMORY.md`. Either name the replacement carrier or retire the roster on purpose.
   Right now the plan does neither, and the recall problem that motivated the whole redirection
   gets quietly worse.
2. **`prevented`, one of the two gate numbers, cannot be computed.** ADR-0015 refuses a sequence
   number and `tool_use` carries no invocation id, so "an attempt event without a matching
   PostToolUse" has nothing to match on. A correlation field is additive and cheap, and it is in no
   issue in the New issues table.
3. **Landing a fix in claude-kit or gh-workflows has no ADR.** ADR-0046 bounds mage's git to the
   repo holding the knowledge base; ADR-0048's amendment extends that to the code repo only. Two of
   the three P0 fixes land in the kit, and the 0.1.0 gate demands three fixes on two units that are
   not mage-memory, which H3 as written cannot deliver.
