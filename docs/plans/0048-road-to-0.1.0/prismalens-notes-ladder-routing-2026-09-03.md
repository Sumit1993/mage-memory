- docs-site-evaluation-playbook.md - rule vs delete. Routed rule because its 13-point checklist is prismalens/Starlight-specific, but it heavily overlaps the existing kit:docs-governance skill; could be a duplicate slated for consolidation.
- coderabbit-says-resolve-but-doesnt.md - rule vs check. A poll-and-classify script (query GraphQL isResolved, detect a verdict phrase) could be built as a real check; routed rule because classifying "verdict present" still needs judgment.

- orchestrator-delegates-everything.md - rule vs delete. Overlaps with the user's own global AGENTS.md Delegation doctrine (agy vs Claude subagent economics); kept as rule since this note's angle (never read files inline, tokens are scarce) is not identical to the global cost rule.
- subagent-watchers-doze-heartbeat-audits.md - delete vs rule. Routed delete because the heartbeat-audit pattern is now fully covered by the kit:anti-stall and kit:unattended-run skills; a case remains for rule if those skills postdate this note and this is actually their source material worth keeping as provenance.
- r1-investigation-usefulness-gate.md - delete vs note. Routed delete as a point-in-time release-gate runbook that belongs in work/, but several of its embedded principles (run each incident twice and grade the worse run, memorization disqualifies a substrate) are genuinely reusable beyond gate #336 and could argue for note instead.
