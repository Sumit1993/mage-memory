2. The redirection

mage stops being a store and becomes the loop that turns a failure into enforcement. The shape that survived three killed gates stays: code narrows, the agent judges, the human merges (ADR-0029, ADR-0046). What changes is the target. The agent no longer asks "is this a lesson worth a note". It asks "which rung fixes this", and the answer lands as a pull request in the repo or kit where it applies.

Two numbers replace the keep-rate gate

NumberDefinitionHow it is counted
preventedA landed fix fired: a deny refused a call, a hook blocked or rewrote, a check failed in CI or pre-commit.PreToolUse attempt event without a matching PostToolUse (deny); hook exit code; CI job status via gh. Ledger committed in the KB, per fix, per unit.
left the queueA note promoted to a higher rung or deleted.PR merged that removes or replaces a note; ledger row.
The ledger is derived from observe events and lives under .mage/ (ADR-0025), never committed. A kit fix counts in whichever unit it fires. tool_attempt and tool_use share the harness invocation id, which is what "matching" means. Ruled 2026-09-04 against the adversarial review.
dead (surfaced, not gated)A landed fix with zero fires in 90 days; a note whose trigger has not been observed in 90 days.ledger age; observe log scan for the trigger signature.

3. The ladder

Highest rung that can carry the lesson wins. A note is the last resort and must name the moment an agent will ask for it. The right column is where the 39 notes in this repo landed when routed on 2026-09-03 (full table in ~/ai-context/mage-notes-ladder-routing-2026-09-03.md).

4. Where things land

Topology is wherever each harness lets config live. For Claude Code that is three scopes, and every output type has a natural one. The kit is a repo the user owns and names at connect; claude-kit is the reference instance. ADR-0036 holds: one harness, no adapter interface until a second harness forces one.

5. Timeline to 0.1.0

0.1.0 is the named release for a proven loop, not a version release-please happens to mint. Migration and retirements ship as patches. No code for the new loop is written until the hand-landed fixes move a count.

10. Traps

  • release-please mints 0.1.0 on any breaking marker. bump-minor-pre-major is on. Retirements are deprecations: no !, no BREAKING CHANGE footer. Add a line to CONTRIBUTING.
  • The docs drift test fails the moment a verb goes. Regenerate the snapshot in the same PR (N5).
  • #200 before anything writes notes at scale. Every Write or Edit under mage/ gets its frontmatter rewritten by the harness. Commandeer stays, so fix the rewrite at the source, or run flatten after each batch until then.
  • Hubs migrate separately. prismalens-kb and sreforge-kb are external-mode stores with their own .mage state and their own hook groups in each code repo. Migrate runs in the hub and in each linked code repo.
  • The plugin marketplace serves a stale copy. A directory-source marketplace snapshots the tree (existing gotcha). Reinstall after N2 or the old skills keep loading.
  • Which binary. Bare mage runs the working tree, npx mage runs 0.0.17. Verification commands in every package say which.
  • gh secondary rate limit. The issue-creation package and the findings puller both hit it at burst. One call per second.
  • #198 first. Migrate rewrites the AGENTS.md block; today that rewrite destroys hand-written content.
  • A user-scope deny rule cannot come from a plugin. Claude Code plugins carry hooks and skills, not permission rules. Deny rules land in the kit's settings fragment and reach the machine through the kit's installer. The kit contract (WP-9) must say so.
  • Worktrees for every lane. Delegated work never runs in a main checkout. Each lane removes its tree when its PR lands.
  • Do not rebuild recurrence. Three gates say deterministic selection of lessons produces nothing. Counts rank the digest. The agent judges. If a package proposes a threshold, it is off spec.

12. Mechanics, stage by stage

Added 2026-09-04 after the loop was walked one stage at a time asking "what code makes this happen". Three operator rulings applied: identities ship in 0.1.0; a check lands as an issue, not a PR; a rule is measured by the corrections and findings tagged with its id. This section is the spec the P1 and P2 tickets point at. ADR-0048 stays one screen and points here. Folds in end-to-end.md.

12.1 Identities

A guard is a landed artifact at rungs 1 to 3: a deny rule, a hook, a check. Every guard and every admitted note has an id of the form <scope>/<type>/<slug>: kit/guard/webfetch, repo/guard/commit-trailer, repo/rule/no-gate2-bypass, kb/note/npx-runs-published. The id is assigned when the proposal is made and travels with the artifact: a comment line in the settings fragment, a header line in the hook script, a suffix [mage:repo/rule/x] on the rule line, an id field in note frontmatter. The ledger, the seen watermark, the guards inventory and the stale pass all key on it.

A signal signature is an exact match on ids, never a fuzzy fold: tool name plus the blocking guard id; the rule id named in a correction or finding; the review bot's rule name plus file path for a finding with no rule id yet. This is how first sight avoids rebuilding the recurrence machinery three gates killed (ADR-0027, 0028, 0038).

12.3 Narrow and rank

Per unit, under .mage/, append-only and folded on read like every other runtime file (ADR-0025, existing convention): proposals.jsonl. Each signature has one state: new, shown (in a digest, with the chapter), declined (the agent or the human said no, with a reason), pending (a PR url), landed (a guard id), dead. The digest shows only new and shown signatures, ranked by count, and never re-shows declined or pending. Pending is confirmed by reading the PR's state; a PR closed without merge becomes declined. Budget stays 3 proposals per pass.

12.4 Judge

Before proposing, the groom skill reads mage guards: the inventory of landed guardes per scope, derived by scanning the id markers in the settings files, the hook directories, AGENTS.md and the notes. Without it the agent proposes duplicates. The proposal is JSON:

{ id, type: deny|hook|check|rule|skill|note|delete   // deny, hook and check are guards, scope: repo|kit,
  rung, skipped: [{ rung, reason }],      // one reason per higher rung, required
  trigger, pointer,                        // required when type is note
  artifact: { path, content }, test?: { path, content } }

The applier refuses a proposal with a missing skipped reason for any higher rung. That refusal is the only mechanical guard on the judge step; the skill text is doctrine the agent may skim. A lazy "no higher rung fits" is caught later by 12.2's climb proposals.

The kit write path. The kit is identified by its remote (committed in the KB's metadata, like hub_repo) and located by a machine binding in settings.local.json (an additive row in ADR-0047's carrier table: derived-but-materialized, like the docs-root grant), because a user's kit checkout is wherever they keep it. Consent to receive PRs is the kit's committed contract file (#216). Landing runs the ADR-0046 machinery in that checkout: branch, commit, push, gh pr create. After merge nothing installs it on a machine until the kit's installer runs; doctor reports a kit checkout behind its remote.

12.6 Fire and count

The ledger is derived, never stored: mage ledger folds observe events per guard id. prevented for a deny is attempts-without-use attributed to its rule; for a hook it is guard_fired rows; for a check it is failed CI jobs whose job name is the guard id, read from the forge. A check that fails for another reason is not a fire, which is why the job name must equal the id. A rule has no fire. Its number is the count of corrections and findings tagged with its id after it landed; a falling count is the rule working, a rising one is a climb candidate. left the queue is note PRs merged that delete or replace a note. Counts are per machine for 0.1.0; the release notes quote the operator's.

12.7 Prune

One dial, dream --stale-days, default 90 for guards. A deny or hook with zero fires in the window is dead and gets a delete proposal. A check with zero fires stays; it costs nothing. A rule with zero tagged repeats is working, not dead; rules leave only by the agent's delete proposal during groom, or by climbing. A note whose trigger has not been observed in the window is dead.

12.8 The note schema

id: kb/note/<slug>
rung: note
skipped:            # why no higher rung
  - { rung: impossible, reason: "..." }
  - { rung: check, reason: "..." }
  - { rung: hook, reason: "..." }
  - { rung: rule, reason: "..." }
trigger: "the moment an agent will ask for this, in one line"
pointer: "path, url or command"

After migration, mage index rejects a note under notes/ without these fields. The pre-commit gate and CI run index, so the check covers the memory hook, imports, hand-written notes and third-party PRs with one piece of code. Existing notes get the fields from the routing table (H1, H2); a note the table routes elsewhere is deleted by the same PR.

12.9 Cost

The PreToolUse arm doubles event volume and adds a process spawn to every call; the memory hook injects the ladder on every memory write. "Footprint unchanged" (ADR-0039) is a claim until measured. WP-5's verify gains a footprint before and after on one real session.

12.10 One failure, end to end

  1. An agent in prismalens ships a changeset naming four packages the config ignores.
  2. The review lane leaves a finding. The puller writes a finding event into prismalens-kb's observe log through mage observe.
  3. Next session start the digest lists it as new. The agent reads mage guards, sees nothing covers it, judges: a check, in the repo, "changeset packages must exist in config". The proposal carries reasons for skipping impossible and hook.
  4. Type is check, so it lands as an issue in prismalens with the assertion. The signature becomes pending. A human or the next agent in prismalens writes the test with job name repo/guard/changeset-packages.
  5. The test fails on the next bad changeset. mage ledger reads the failed job by name: one prevented.
  6. The same story with a WebFetch redirect lands as kit/guard/webfetch by PR in the kit; the next attempt is an attempt-without-use matched to that rule.

The three repos are the three scopes: each code repo and its KB (project), claude-kit (user), gh-workflows (org, after 0.1.0). mage owns no scope; the opinions live in the kit, the checks live in the repos.
